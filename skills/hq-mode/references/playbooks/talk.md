# Talk

**You own a deck the audience can follow at speaking speed.**

1. Read the source text and any exemplar: a peer's deck, a template. Follow its structure and
   register, never its wording.
2. Text-only outline in md first. Discuss content before any PPTX exists.
3. One folder per slide; subagents build slides in parallel. Go in order: text options in the
   terminal, then 2 to 4 rendered options. The user picks or combines.
4. Slide rules: 24 pt default, 20 pt floor; phrases, not sentences; formal titles that state a
   conclusion; colour only with meaning; every named tool explained in one plain line; round
   numbers; citations as author, journal, year. Show how and why, not only what.
5. Illustrations: raster images via Codex in a subagent. Text stays in PPTX boxes.
6. Merge with a reproducible build; archive the slide folders. From then on edit the merged
   deck, and port the user's hand edits into the build source each time.
7. Animations: Appear and Disappear only, a few steps per slide, by section.
8. Render every slide and click state through PowerPoint, not LibreOffice, and look at each for
   overlap, clipping and the Repair dialog. Check the deck is closed in PowerPoint before you
   write it.
9. Speaker notes last: the spoken script only, with contractions and transitions. A line the
   script never says is a candidate for cutting from the slide; propose it, don't do it.
10. Recorded talks: per-slide recordings, short gaps, PowerPoint-exported frames. Bad audio →
    ask for a re-record; never denoise.

**Reply:** the deck path, slides changed, preview images checked, and open choices.
