# Domain-bias audit, deeper pass: mattpocock/skills and pstack

Research note for #69, part of the map #62. A deeper pass over the items #65 adopts, with supporting files read in full.

**Sources:** `mattpocock/skills@49dd158`, `cursor/plugins@978ca6e` (pstack v0.15.17), both checked out locally.
**Prior audit:** `origin/research/science-fit-audit:research/science-fit-audit.md`.
**Checked:** 2026-10-10.

**Method.** I read every file in each of the 52 in-scope skill directories in full, through `cat -n`. That covers every `SKILL.md`, reference page, template, script and `agents/openai.yaml`.
Every passage, line number and count below comes from that reading at the pinned commit. Tier: **read**. Each classification and verdict is a **judgement**.

**Classes (the lab's bar).**
- **Illustration**: a web, product or engineering example that a reader translates on sight. It earns no edit.
- **Steers wrong**: an instruction, default, template, checklist or decision rule that makes an agent do the wrong thing, or skip the right thing, in lab work. It earns an edit, and the edit only ADDS a capability.
- **Safety-owned**: steers wrong only because it lacks a lab safety rule (confirm `sbatch`, Edison spend). By the lab's rule those rules live in `lab-*` skills and are not copied upstream, so no edit.

**Verdict column vocabulary.**
- *unchanged*: same verdict and same edit list as the prior audit.
- *as-is→edit*: the prior said adopt as-is; this pass finds a steers-wrong passage.
- *edit no longer needed*: the prior's edits are illustration-level or safety-owned.
- *edit list grows*, *edit list shrinks*, *edit list changes*: still adopt with edits, and the edit list moved (*changes* = some added, some dropped).

Paths: mattpocock `x` is `skills/engineering/x/` or `skills/productivity/x/`; pstack `x` is `pstack/skills/x/`, principles `pstack/skills/principle-x/`.

## What the prior audit got wrong

- **unslop terms of art.** It named "landscape" and "scaffold", which rules 7 and 26 already qualify ("(abstract)", "as a metaphor"), and missed "locus", which is unqualified. It proposed a methods-voice edit for rule 29, whose own exception (:58) already allows that passive. It missed rule 30's statistical "significantly" and rule 13's en-dash ranges.
- **diagnosing-bugs.** Its loop-builder edit mostly restates :28, :33, :34 and :45. It missed the passage that actually blocks lab bugs, the :63 speed gate.
- **Lab safety rules copied upstream.** Four proposed edits are lab safety rules, which the lab's edit rule keeps in `lab-*` skills: diagnosing-bugs 2, research 3, never-block-on-the-human, and the login-node half of benchmark-checklist 1.
- **pr is misdescribed.** "Evidence ranks screenshots, then test output" is not what it says: the template slot accepts "output", and :162 limits screenshots to visual changes.
- **technical-writing protocol edit.** It duplicates :69 (STE's warning before the step).
- **show-me-your-work edit 3 and code-review edit 2.** Both duplicate existing text (:21 and :27–32).
- **A proposal that introduces a science hazard.** The prior's `prototype` third branch ("2 or 3 variants side by side: normalisations, parameter choices") and its `exhaust-the-design-space` reason both invite choosing an analysis by its result. Either one needs a criterion fixed before the variants run, and a report of every variant tried.
- **benchmark-checklist closure.** The prior repointed only the Opening a PR edge. :38–39 also point at the Perf issue and Hillclimb playbooks, which are "idea only".
- **Principles read only for UI words.** The prior looked for UI vocabulary and so passed `model-the-domain` (temporal decomposition vs pipeline stages), `boundary-discipline` (trust the types), `make-operations-idempotent` (PID locks) and `sequence-verifiable-units` (free per-unit checks).
